# 上下文与消息交互验收

1. 同一会话依次切换 Accept Edit → Readonly → Plan，询问当前模式和可访问目录。应知道新状态；Readonly 写文件被明确拒绝，主代理可主动进入 Plan。
2. 给会话设置目录限制后继续对话，Agent 应知道具体目录和任意 shell 被禁用；恢复全部目录后也应得到新状态。
3. 使用上游明确不支持的原生附件触发错误。错误记录应标记未纳入上下文；关闭该文件类型能力后发送普通文字，应能继续。旧版已失败的附件记录也应恢复；先前成功发送的附件应保留。
4. 点击已发送图片、PDF、Markdown、TXT 附件，检查只读预览；PDF 翻页。其他类型用“其他应用打开”选择系统应用；没有可用应用或文件缺失时应显示原因。
5. 复制用户与 Agent 回复，Markdown 应复制原始正文。停止生成后，通过消息菜单编辑正文、取消某个附件、删除消息。下一轮使用修改后的历史，操作本身不重新生成。
6. 删除带工具调用的 Agent 消息后继续对话，不应出现孤立 tool_result 错误；已生成文件不应因此被撤销。子代理页面只提供复制/预览，不提供编辑/删除。
7. 生成修改包含长代码行的文件，收起只显示红绿增减数；展开后看到红删绿增，自动折行时不产生新的文件行号。

缓存前缀稳定性与失败重放边界由 JVM 回归测试检查。供应商的实际缓存命中还受模型、缓存期限、最低长度等服务端条件影响，不能仅凭 UI 判断。
