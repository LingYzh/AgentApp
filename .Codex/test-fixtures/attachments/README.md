# 附件与子代理验收

安装新 Debug APK 后，将同目录的 `visual-check.png` 和 `notes.txt` 自行复制到手机「下载」目录。本次不自动操作手机或导入测试数据。

1. **能力设置**：进入模型配置，获取模型列表。能返回能力的接口自动勾选；接口未提供信息时，按供应商实际支持情况手动打开图片/PDF，保存。切换不同模型再回来，确认各模型的覆盖独立保存，刷新不会清掉手动设置。
2. **图片**：在聊天中点回形针选 `visual-check.png`，确认标签为「模型直接读取」。发送“请说出色块从左到右的颜色，以及底部校验码”。预期红、蓝、绿，`KITE-831`。只有文件也能发送；退出再打开会话，附件仍在。
3. **文本/工具**：选 `notes.txt`，保持「工作区文件」，发送“读取附件并告诉我剩余任务数和校验码”。预期 1、`MAPLE-472`；工具调用与结果应合为一条记录，可展开参数和完整结果。
4. **PDF**：自行选择一个 PDF，开启对应模型的 PDF 能力，以「模型直接读取」发送，核对模型能读到页面内容。不同 OpenAI 兼容网关是否接受 PDF，仍取决于供应商实际协议。
5. **子代理**：发送“委派一个子代理读取刚才文本附件的工作区路径并核对任务数量，返回结论”。点主会话右上角的会话面板，选择子代理进入独立只读页面，观察状态、实际模型和内容；返回后父任务继续。会话总列表应只新增主会话。父任务停止时子代理也停止。
6. **迁移**：导出含附件与子代理的主会话，再以「副本」导入；新主会话应带自己的子代理和附件。只对这个新测试副本执行删除，确认子代理随之删除，原会话还在。
7. **失败边界**：给包含原生图片的会话切换到未开启图片能力的模型，再发送文字；应提示能力不匹配且保留草稿。未配置模型时也不应清空草稿。一次选择超过 8 个附件应提示上限。

每条消息最多 8 个附件；上传与原生读取不再设置本地字节上限，上游返回的大小错误会显示在会话。音频/视频的原生传递仅在 Gemini 协议并开启对应能力时提供；自定义模板尚不支持附件读取。大文件可以作为工作区文件保存，但现有工具不保证解析任意二进制格式。

历史版本的子代理没有父 ID，不能可靠自动归属；这类历史记录继续保留在总列表。新建的子代理按新的关联管理。

## 本轮新增检查

8. **Markdown**：让模型生成带标题、粗体、引用、任务列表、代码块和表格的回复；应渲染为格式化正文，长按可选择文本，链接可打开。
9. **附件位置**：同时发送文字和文件，文件卡片应位于用户文字气泡上方。
10. **大图**：选择一个超过 4 MB 的真实图片，分别用原生方式发送和工作区方式发送并让模型 read_file；两者均不应触发本地 4 MB 拒绝。上游的限制仍由上游返回。
11. **Diff**：让模型先创建文件再修改几行；工具记录中点「查看更改」，应看到本次新增/删除行。文件查看页的「更改」页应显示该文件最近一次由工具记录的修改。旧版本修改没有前文快照，不能追溯补出 diff。
12. **子代理中止**：运行较长子任务，从抽屉进入，点「中止」先取消弹窗，确认任务继续；再输入理由并确认。子代理应变为已停止，主代理收到理由后继续行动，不能在子代理页输入消息或切换模型。主代理流中不显示委派 JSON 和子代理返回全文。

大文件依然受手机可用内存、磁盘、网络和供应商限制；原生请求目前采用内存 Base64 编码。独立迁移包仍保留总体 64 MB 校验，和发送附件大小无关。
