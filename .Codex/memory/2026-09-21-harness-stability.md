# 2026-09-21：首轮稳定性与列表交互修复

## 已确认的环境与范围

- 用户设备：Nubia NX809J，Android 16 / API 36，已通过无线 ADB 连接本机。
- 应用 ID：`com.Ling.actant`。用户自用，不上架应用商店。
- 用户反馈主要聊天与工具流程已基本跑通，技能功能尚未充分使用。
- 当前阶段先完善聊天与 harness 稳定性；设备接管、Shizuku 和 root 接入尚未实施。
- Agents 从会话列表经侧菜单首次进入时，用户观察到约半秒的列表延迟；圆角列表项存在方形 ripple。

## 实现

- 列表刷新从 LifecycleResumeEffect 提前到 LifecycleStartEffect，移除等待入场动画完成的加载条件。
- Agents 配置读取移到 IO 刷新阶段，避免各列表项在组合期间反复读文件；首载显示加载态，避免误报空列表。
- Agents、会话、Agent 选择、模型、文件、记忆和技能卡片使用 Card 的 onClick，让 ripple 按卡片形状裁剪。
- 聊天模型选项由 StateFlow 提供，不再随流式重组反复读取配置；发送和模型切换持久化移到 IO。
- 聊天运行中提供停止生成按钮；网络取消覆盖等待响应头和阻塞的响应体读取，包括自定义 Provider。
- 引擎保留中断前的文本与思考内容；模型错误、轮次上限和取消路径补齐未完成的工具响应；错误流不会触发工具操作。
- 子代理返回最后一次执行结果，避免失败后误返回较早的回复。
- 修正模板设备测试中的包名断言，使其与实际 applicationId 一致。
