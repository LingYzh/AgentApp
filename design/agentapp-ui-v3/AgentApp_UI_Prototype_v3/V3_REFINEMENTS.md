# AgentApp UI v3 · 本轮修改与验收

2026-09-22 · 源码基线 `2c947234ab0d29ede6e999193717288363195b7a`。
本文件取代 v2 第 7 项工具呈现方案及早期“完成 N 个步骤”的包裹结构。v2 其他功能要求继续有效，已整合入 DESIGN_SPEC.md。

## 1. 工具记录是对话中的行，而不是一张卡片

外层 `ToolActivityRow` 与工具组均无 BorderStroke、底色、圆角卡片或额外水平内边距。沿用正文的左右边界。不要在外面再套 Surface → Card → Column padding → 内部代码卡；展开后的唯一内容底色只属于 Shell/Diff 本身。

收起态主轴：图标 → 动作文字 → 可选文件名/计数 → 箭头。箭头紧跟内容，不需要在整行右端另放“详情”按钮。整行可点击/键盘激活，展开有明确语义与状态。原生最小触控区 48dp，图标视觉约 18dp；窄屏优先截断文件名，动作、计数和箭头不丢失。

主会话按既有 assistant/tool 消息的顺序显示，不为美观重排执行时间线，不把原本多次调用合并成一次记录。子代理仍只读，不能通过查看详情获得编辑或再次委派能力。

## 2. 命令：收起一句话，展开一份执行记录

已完成时，收起正文严格为“运行了命令”。不展示完整命令、参数 JSON、输出摘要、耗时或右侧成功徽章。执行中/待批准/失败/中止必须相应显示“正在运行命令 / 等待命令批准 / 命令执行失败 / 命令已中止”，不能为了统一短句把未执行说成已经执行。

展开：轻量 Shell 内容区，先显示 `ToolCallInfo.argumentsJson` 中真实 command，再显示与 callId 对应的工具返回。命令和输出视觉分组，空输出不等于缺少结果：已完成且确实没有文本才显示“本次命令没有输出”；未返回显示等待，失败保留真实错误。

有真实退出码时展示；没有则省略，不推断 0。原型 fixture 自带 exitCode，不意味着生产数据已新增该字段。命令内换行、缩进完整保留。不要把复合命令拆成多次已执行记录，不单独执行输出里的命令。

支持原文复制、换行/不换行、内容区域的局部滚动以及“展开高度”。复制不带 HTML、可视的 `$` 提示符或虚构元数据。没有弹窗，没有“重跑命令”按钮；要执行新命令仍走原有模型工具和授权链。

## 3. 文件编辑：收起统计，展开 Diff

收起：`已编辑 FilesScreen.kt +1 −1 ›`。文件名下划线表示该可展开记录的目标，不产生与整行冲突的导航热区。展开行标题可简化为“已编辑的文件”，Diff 顶栏仍保留文件名和统计。

数据来源：成功 write_file/edit_file 对应 `ChatMessage.fileChange`，使用现有 `FileChanges.diff(change)` 得到 FileDiffResult。`addedCount / removedCount` 是行数，不是字符数。新增显示新行号、删除显示旧行号，保留上下文行；显示 +/- 符号和侧线，不能只依赖颜色。

Diff 保持原有缩进和代码空格。默认横向滚动长行，支持切换换行；折行续行不重复行号。较长 Diff 有局部滚动与原地展开高度；不要改成通过 FileDiffDialog 才能查看完整详情。真实大文件应增量渲染，保留现有计算预算。

`previewOmitted / usedFallback / fallbackReason` 必须显式可见。没有快照就写“无法显示此次 Diff”，不能重新读取文件并把当前内容冒充当时快照；没有完整差异时不展示貌似精确的 +0 −0。编辑失败不出现成功统计。新建/删除按实际工具语义命名，不能全部误标为编辑。

统计和快照属于已经执行的记录，不是待接受补丁。展开、复制或删除会话不执行、重跑或撤销文件修改。

## 4. 更连续的 UI 变化

不仅给 route 增加进场。v3 改为保留同页节点/稳定 key，再对变化区域做局部进入退出、尺寸或位移过渡。完整矩阵见 MOTION_MATRIX.md。

包含：页面与返回、抽屉、面板进入退出及面板间替换、工具/高级参数折叠、选中/禁用/默认 Provider、多选管理模式、标签切换、附件加入移除、按钮图标状态、代码换行/复制/高度、顶部反馈占位、主题色与评审宽度切换。

收起动画在高度收完后移除内容；展开动画真的改变布局高度，下面的正文自然下移，不用 transform 把内容画到别的控件上。快速反向点击从当前状态接续，取消旧动画完成回调，最后一次用户操作胜出。动画不是网络锁，停止/取消应立即触发生命周期与执行逻辑。

例外不是遗漏：文字输入与光标立即反馈；120ms 流式解析/逐 token 不反复动画；手指拖动即时跟随，松手再完成视觉收敛；系统键盘/文件选择器跟随 Android 原生过渡，不用浏览器假键盘模拟。减少动态效果时到达相同终态，不能留下隐藏但可交互的旧内容。

## 5. 图标与文字对齐

统一按钮内容为 `Row(verticalAlignment = Alignment.CenterVertically, horizontalArrangement = Arrangement.Center)`，Text 与 Icon 是并列节点，图标不按字体 baseline 排版。两者之间约 6–8dp，chevron 约 14–16dp，处于文字右侧。48dp 点击区与 18dp 图标视觉大小分开，不用负 margin 或改字高“凑齐”。

浏览器为 inline-flex + align-items:center + 明确图标尺寸；文字 span 统一 line-height，SVG display:block。测试以两者 bounding box 的垂直中心检查，而不仅是肉眼看字。系统字体放大后允许按钮合理扩宽，长标签可缩略，不裁掉箭头。

## 6. 启动先新对话，历史不消失

核对仓库：MainActivity.kt 的 `startDestination = Routes.CONVERSATIONS`；CHAT 路由需要真实 conversationId；ConversationsViewModel.create() 一调用就落盘。

因此原生改造不是把字符串改成 CHAT，也不是在每次 onResume 强制导航：

1. 新增顶级 `NEW_CHAT`（例如 `newChat`），无会话 ID；冷启动默认该入口。
2. 该页存储 NewChatDraft：Agent、模型覆盖、权限/目录、思考强度、正文和已导入附件引用。导航/重组/旋转不能创建 Conversation。草稿暂存仅用于恢复，不成为历史。
3. 首次有效发送时由单一协调器在互斥或状态锁下生成 ID、保存会话+首条消息、消费草稿并开始请求。新页面接手同一个任务所有权，不能由于从 NEW_CHAT 导航到 CHAT 销毁 ViewModel 而取消刚发出的请求。
4. 连点发送不创建多个会话；提交失败保留草稿和错误。创建成功后导航/消费回执必须幂等，重试不重复写首条消息。
5. 成功进入 chat/{id} 后不再保留一个已被消费的旧草稿；返回到 NEW_CHAT 时是新的空草稿。历史入口保留在抽屉，加载历史仍进入其原 ID。
6. 切后台再返回、旋转、权限设置/文件选择器回来、恢复已有任务栈，都保持当前页面、输入和会话。此处“默认新对话”指没有现存导航状态、没有明确目标 Intent 的初始进入，不覆盖合法恢复或显式打开某个会话。
7. 无 Provider 时新对话展示配置引导，不创建空会话。未发送草稿的附件退出/清理遵循已有附件所有权，不能删除共享或已被历史引用的文件。

原型实现了演示层的“初始 home / 首次发送唯一记录 / 重复新对话不留空记录”。真实 Android 导航与事务尚未改动，Codex 必须本地实现并验证上述恢复与任务所有权。

## 7. 本轮验收

| 场景 | 预期 |
| --- | --- |
| 收起的命令 | 只有动作/状态文字，无参数/输出/框线 |
| 展开命令 | 原地 Shell、原命令与真实返回、无返回/空输出区分 |
| 收起编辑 | 文件名与真实 +/- 统计；长路径不把箭头挤掉 |
| 展开编辑 | 宽度与正文一致的 Diff、正确行号和局部滚动 |
| 缺失/裁剪快照 | 明示降级，不伪造差异和统计 |
| 连续展开收起 | 最后状态正确，不留旧层、不抢滚动 |
| 下拉按钮 | 图标/文字同排居中，浅深色与 360 宽度通过 |
| 新对话与首发 | 冷入口 home，无空会话；首次发送只创建一次 |
| 返回前台 | 不强制重置；该项需 Android 实机验证 |

所有 UI 中的 Shell/Diff 均为样本，不说明仓库已经执行对应改动。浏览器验证不代替 Compose/Android 验收。
