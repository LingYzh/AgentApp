# AgentApp UI v3 · 统一设计规格

## 0. 产品与实施边界

Android个人LLM harness，Kotlin + Jetpack Compose + Material 3。保留聊天、模型接入、Agent配置、文件、Skills、记忆、权限、单层子代理和迁移。没有后台常驻服务、root/Shizuku、屏幕控制或远程插件市场。本交付没有改变这些边界。

视觉：暖白/暖炭灰、陶土强调、阅读优先，保留AgentApp身份。配色沿用v2，原型不是Claude/Gemini/ChatGPT逐像素复制。样本、临时数据和评审界面不能进入正式App。

## 1. 信息架构与启动

冷启动落在独立NEW_CHAT草稿页。历史通过侧栏进入；无永久底部Tab占据聊天空间。抽屉提供新对话、最近会话、Agents、工作区、模型配置、Skills、记忆、设置。侧栏与会话内面板用途分离：会话面板只包含该任务的计划、子代理和产物。

首次有效发送才创建会话，连点幂等，不因打开应用创建空历史。后台恢复/旋转/外部选择器返回保持当前会话。新增NEW_CHAT路由、草稿所有权和首次提交事务详见V3_REFINEMENTS第6节；不能直接把带ID参数的CHAT设为默认，不在onResume重置。

## 2. 颜色与排版

权威值见design-tokens.json。浅色background #FAF9F5、surface #FFFFFF、正文#262624；深色background #262624、surface #30302D、正文#F1F0E9。实心actionContainer浅色#A34F36/深色#A9563D，onAction在两种主题均#FFFFFF。深色轻量链接/文本强调#E6A086，不用它填充主按钮后再硬配白字。

保留system/light/dark语义，不自动启用跟随壁纸的动态配色。系统字体，不分发品牌或系统字体文件。大标题可使用系统可用衬线，聊天正文无衬线，代码等宽；支持系统字重/字号放大。

正文16sp/约28–29sp行高；工具摘要14sp；辅助文字12sp左右；代码原生建议13sp/21–24sp。网页窄屏样本含更紧凑代码字级，仅作视觉参考，Codex要以dp/sp和设备可读性验证，不照抄截图物理像素。

页面左右22dp；composer左右14dp；section间距24dp；工具外层无额外左右padding。按钮触控区48dp，视觉图标约18–22dp。Icon和Text用同一居中Row，chevron在文字右侧，不能按文本基线摆SVG。

## 3. 聊天与输入

用户浅暖灰右对齐气泡；助手无气泡正文。顶栏保持返回、助手/主题和会话面板。输入容器圆角23dp，附件在内部独立chip；底行附件/模型选择/发送。执行中发送转停止，复制与滚动仍可用。

底部紧凑控制栏：权限、思考、上下文。正文允许滚动，输入/安全区固定；系统键盘弹起跟随真实imeInsets，禁止套假键盘。流式跟随仅在用户仍处于底部时继续，用户上滑不强制抢回。不能为减轻UI而藏掉等待审批和失败状态。

复制、编辑和删除消息保留：编辑只改历史，不自动重跑工具或发送；删除消息不是撤销文件修改。未纳入后续上下文的消息需可辨识，压缩原始历史继续保留。

## 4. 工具记录（v3取代旧外层步骤卡片）

所有主/子会话中的工具调用直接作为无外框展开行排列。禁止外层“完成N步骤”Card和多层Surface。组本身无底色、描边、水平padding；Shell/Diff内容展开后可有一个浅底代码区。

命令完成收起只显示“运行了命令”；展开显示真实command及该call对应结果。运行、未批准、失败、中止用真实状态文字，结果缺失不能宣称完成。输出为纯文本、安全渲染，局部滚动/换行/原文复制，现有记录不提供直接重跑。

编辑收起为“已编辑 文件名 +增行 −删行”。展开内联Diff：文件头、增删统计、上下文、新/旧行号、+/-符号、低饱和红绿底和侧线。长行横向滚动，可换行/展开高度。缺快照/预算降级明确说明，不能伪造精确计数。

ToolCallInfo.argumentsJson + ChatMessage.content/isError/fileChange以toolCallId关联；统计和行来自FileChanges.diff。不要把presentTool摘要替代真实结果，不重新读取已变动文件当历史快照。展开状态键包含conversation/message/call，主题/流式刷新不丢失。

## 5. 思考强度与模型能力

思考是独立离散滑块小面板，不混入模型选择。当前中文强度+wireValue置于上方，可点击进入详细popup；重置恢复跟随Provider。只使用ReasoningSupport.efforts的实际支持档位。null表示继承而不是none，继承未知默认不伪造中档。拖动预览，松手提交，执行中只影响下一次模型请求。

详细列表保留中文、canonical值与当前adapter字段说明。协议预算/温度冲突继续使用已有映射，不在UI重新实现。自定义模板不自动注入思考参数。

模型选择按Provider分组并支持搜索。每个modelId显示image/pdf/audio/video有效能力图标、文字和来源；capabilityOverrides优先discoveredCapabilities，无声明不猜测。工作区文件工具读取不是媒体原生输入，图标也不是系统存储授权。

## 6. 上下文

复用8类：system/tools/environment/user/assistant/results/attachments/summary及既有颜色。设本地分类合计T，已知容量C：分母D=max(C,T,1)，分段宽tokens/D，保留余量。未知容量D=max(T,1)，仅画组成，文字“容量未配置”。不强行为零值加最小宽，不隐藏超额。

图例tokens/T为占已用比例，和总体占容量比例分开。服务端上次输入/输出/缓存/思考用量单独展示，未报告不等于0，缓存不要重复相加。压缩须确认、可取消，原始历史保留；仅空闲主会话允许相关操作。

## 7. 权限、审批与任务

保留Accept Edit、Plan、Auto、Readonly原语义。Auto取消App审批不代表突破Android UID；显式目录限制和模式不能被命令白名单绕过。计划阅读和执行确认分离，默认不是自动放行；危险操作不改为自动消失提示。

子代理只读，不可再次委派，显示真实running/completed/failed/cancelled；需要授权回主会话，不能以子代理UI扩大权限。停止取消必须贯穿Provider/Tool/child，不能吞掉CancellationException。

工具UI轻量化不影响执行授权：阅读Shell/Diff不是批准操作，展开命令不执行命令，批准还是原有明确入口。

## 8. 管理页

Provider：正常模式radio设置全局默认，主体/右箭头编辑；管理模式checkbox多选，主体只切选中，不能同时改默认或导航。移除同卡片重复设默认/编辑/同义...。顶栏列表菜单保留导入/导出/管理。编辑页保留协议、地址、Key、模型、能力与上下文、参数、请求头、自定义模板、获取模型和测试连接。

Agent：头像/名称/描述/系统提示/默认模型/工具。空tools表示全部工具，不能误译为禁止全部。Skills/记忆/文件保留真实格式、批量选择、导出与删除确认。技能不虚构启停字段/市场。多类列表统一管理模式，但数据语义各自保留。

文件预览与源码、最近变更分开。对话工具Diff详情必须原地；正常工作区文件导航仍可下钻。完整备份恢复与独立配置迁移分开：无Key导出也排除附加头；冲突先prepareImport预览，未经确认不写；副本/更新规则不改。

## 9. Markdown统一阅读

聊天/文件/计划/记忆共用样式token和已有MarkdownDocument分块，长文阅读页可有更大的外层标题，不对所有聊天H1套营销式大字。标题层级、段落间距、嵌套悬挂缩进、引用侧线+浅底、只读任务状态、行内代码底色一致。

代码块：语言和复制/换行操作头，等宽正文，默认长行局部横滚，复制源文本。宽表在容器内横滚，不挤成窄列或撑大整个页面。语法色只用于呈现，未知语言退回纯文本。

保留原生SelectionContainer、安全链接scheme、现有解析器、120ms后台采样和旧文档保持可见。不为每个token重播fade，不因主题变化重建文本选择。原型演示解析器不可复制替换生产CommonMark解析器；不新增HTML执行、远程脚本或未实现的公式/图形能力。

## 10. 反馈与动效

普通横幅在当前页面或弹层标题下的占位区，出现/收起改变布局高度，不浮盖composer或确认栏。全局只一份活动反馈；错误信息仍保留在发源页面。普通提示可关闭、hover/focus暂停计时；正式采用无障碍建议时长，不硬编码网页4.5秒。

每种有意义的UI状态变化尽可能以小范围transition连贯呈现。以MOTION_MATRIX.md为验收清单，避免只有NavHost动画而表单/列表/工具仍跳变。支持快操作打断，最后意图胜出；同页保留key/滚动/焦点。系统减少动效到相同终态。文本输入、手势跟随和流式token不延迟/重复动画。

## 11. 验证范围

26页含25Markdown、26工具样本，这两页是评审/验收入口，不要加入正式App导航。样本所有状态已生成浏览器截图。原生必须另验小屏、大字体、IME、TalkBack、返回/生命周期、真实Provider和文件操作。完整测试边界见TEST_REPORT.md。
